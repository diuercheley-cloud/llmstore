## Real Execution Readiness

The real-execution readiness gate blocks production-like posture when any of these conditions are true:

- `AGENT_EXECUTION_ENABLED=false`
- `AGENT_EXECUTOR_MOCK_MODE=true`
- `AGENT_EXECUTOR_DRY_RUN_MODE=true`
- durable queue is disabled
- scheduler is enabled without the queue
- sandbox is disabled in production-like posture
- connector mode is invalid or `real` without outbound HTTP enablement
- operator mode is not `real`
- execution hot paths still contain placeholder fallbacks such as implicit simulated tool output or connector `NotImplementedError`

Current gate implementation:

- configuration checks via `RealExecutionReadinessService`
- worker heartbeat checks from `agent_worker_heartbeats`
- code-integrity scan for execution hot paths
- markdown/json artifacts generated by `scripts/dev/real-execution-readiness.sh`
